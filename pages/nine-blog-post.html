Generative pages in Dynamics 365: what they are and 12 ways to use them

The short answerGenerative pages let you describe a screen in plain English and get a working page inside a Dynamics 365 app. Microsoft's app agent writes the code and connects it to your Dataverse tables, and you refine it by chatting. They are generally available and fit best when a team needs one focused screen that standard views lack.

What is a generative page?

Dynamics 365 Sales, Customer Service, Field Service and Project Operations run as model-driven apps in Power Apps. A generative page is a new kind of page you can add to those apps.

You describe the page you want. You pick the tables it should use. You can even attach a sketch of the layout. Microsoft's app agent then plans the page, writes React code, and shows you a live preview. If something is off, you tell it what to change, or you edit the code yourself.

The AI does its work while the page is being built. The finished page is an ordinary screen that reads and updates your Dynamics 365 records, and we test it with your users' real security roles before anyone relies on it.

How do you build one?

There are two ways.

Way 1

In the browser. In Power Apps, open your model-driven app in the app designer. Choose Add page, then Generative page, then Describe a page. Type what you want, add up to six Dataverse tables, and select Generate page. You watch the agent outline its plan, write the code and render the result. Then you save and publish.

Way 2

With an AI coding tool. Microsoft now recommends building generative pages with AI code generation tools such as GitHub Copilot CLI or Claude Code. A planner agent proposes the pages, tables and solution first. You approve the plan, and it builds and deploys. This route can create several pages and their supporting tables in one run.

Either way, a person still checks the result. Microsoft is clear that the maker is responsible for validating the code before users rely on it.

Where do generative pages show up?

A generative page can live in three places:

  • In the app navigation, as its own page.
  • Inside a form, in a section or tab. The page gets the current record automatically. So you can keep the standard form for data entry and add a richer view beside it.
  • Opened from another page or button, with the record passed in.

To see three of these built, with the limits stated plainly, read three screens we built on demo data.

What are 12 ways to use generative pages?

Here are twelve uses for small and mid-sized teams on Dynamics 365. Some come from Microsoft's own examples, three are the screens in our demo, and the rest are common requests.

  1. 1SalesTop accounts board.A ranked gallery of key accounts with revenue and last activity. Microsoft's own examples include an account card gallery and a top accounts dashboard.
  2. 2SalesPipeline board.Opportunities as cards by stage, so reps see the whole pipeline on one screen.
  3. 3SalesAccount 360 on the account form.Relationship health with its reason, win rate, open pipeline by month, contacts and open cases, on one tab before a call.
  4. 4SalesOpportunity command center.The first tab on a deal: revenue, probability, stage, products, overdue follow-ups in red, and the quote.
  5. 5SalesQuote approvals.A list of pending quotes. Tick the ones you are happy with and approve them together. Microsoft shows the same pattern with an order review page.
  6. 6ServiceActive cases command center.Case list, status and trend charts, filters and SLA flags on one page.
  7. 7ServiceCustomer history on the case.Past cases and recent activity for the same customer, shown inside the case form.
  8. 8ServiceDocuments beside the case.Files from a SharePoint list shown next to the record. Connector support is still in preview.
  9. 9Operations and fieldJobs on a map.Open work orders or incidents on a map for dispatchers. Microsoft lists "incident reports on a map" as an example prompt.
  10. 10Operations and fieldEquipment gallery with photos.Customer assets or products as picture cards, so people find the right one by sight, not by ID.
  11. 11Leadership and financeRole-based home pages.One start page per role, showing that person's open work.
  12. 12Leadership and financeUnbilled time review.Time entries waiting for approval or billing, by project.

When should you not use a generative page?

Generative pages are not the answer to everything. Pick something else when:

  • The job is simple data entry. A standard form is more consistent and easier to support.
  • You need heavy reporting over a lot of data. Use Power BI. Community testers have noted that generated pages can load data into the browser, which does not suit large volumes.
  • People need to ask questions, not open a screen. Copilot in Dynamics 365 answers questions about your data in a side pane.
  • The need is a conversation or an automated process. Build an agent or workflow in Copilot Studio.
  • You need one control reused across many forms. A PCF code component fits better.
  • Several makers must edit the same page at once. Generative pages do not support co-authoring yet.

Also expect to iterate. A new prompt can change parts of the page you were happy with, so test after each change.

What do you need to get started?

You need a Dynamics 365 or Power Apps environment with a model-driven app. Microsoft says the maker experience does not need any extra AI or message credits.

For in-browser building, the environment must be in the United States, Great Britain, Australia or Singapore, and prompts are in US English. The AI coding tool route works worldwide on public clouds.

What is the status and licensing (November 2026)?

As of November 2026, generative pages in model-driven apps are generally available. Using Power Platform connectors, Dataverse custom APIs and Application Insights telemetry with generative pages is still in preview. Microsoft does not list a separate end-user licence for generative pages. Check your own licensing and admin settings with your partner before you build. Features change often, so confirm details on Microsoft Learn.

Frequently asked questions

What are generative pages in Dynamics 365?

They are pages in model-driven apps that Microsoft's app agent builds from a plain-language description. The agent writes React code that reads and updates your Dataverse data.

Are generative pages generally available?

Yes. Generative pages in model-driven apps are generally available. Using Power Platform connectors and Dataverse custom APIs with them is still in preview.

Does building generative pages cost extra?

Microsoft says the maker experience doesn't require any additional AI or message credits. Users still need a licence for the app the page sits in.

What data can a generative page use?

Up to six Dataverse tables per page. Power Platform connectors and Dataverse custom APIs are available in preview.

Can I edit the code?

Yes. You can keep chatting with the agent or edit the code directly. Each save becomes a new version you can compare.

Do generative pages replace Power BI or Copilot?

No. Use Power BI for heavy analytics, Copilot for questions about your data, and generative pages for focused working screens.
