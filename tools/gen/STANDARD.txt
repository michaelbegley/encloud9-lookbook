The standard in one screen
A page is done when it clears every gate (pass or fail, no exceptions) and scores 28 of 32 on the eight scored areas, judged by a reviewer who did not build it, and Michael approves it.
Gates first. One failed gate means the page is not done, whatever its score. Gates cover the things that embarrass enCloud9 in public: a made-up fact, a broken link, an accessibility error, a leftover bracket.
Then the score. The eight areas and the 0 to 4 scale are the ones the page builds have used since 4 Nov (RUBRIC.md), so earlier reviews still compare. What changes is that every page type and the blog now get their own extra checks inside those areas.
Two levels of done. Draft 2 done = every gate except the launch gates, and 28 or more. Launch ready = also the launch gates: no brackets anywhere, real forms, prices re-checked that week, Brian's sign-off on anything under his name.
One page at a time. Freeze the page, run the checks, independent review and score, fix once, re-check, Michael approves, then the next page. Nothing moves on while a page sits below 28.

Checks every page must pass
Every page type, blog posts included, runs these. Gates are pass or fail; the eight areas are scored 0 to 4 (4 = every point met, 3 = one real gap, 2 = two gaps or one a buyer hits on the first screen, 1 = mostly missing, 0 = absent).

How the one-page-at-a-time review runs
The site-wide structure audit runs first (menus, footer, breadcrumbs, buttons, every link going to the right page, and the URL map Brian asked for). Then each page goes through the same seven steps, one page at a time.
Freeze. Pull the latest, save the file's hash, and list the page's sources and open brackets.
Run the checks. qa.js, crawl.js and the cross-page script cover gates G2 to G8 and the automated half of the areas. Results go in the page's review file.
Independent review. A separate agent that did not build the page gets only the page, this standard and the page's sources. It traces every fact (G1), scores the eight areas with a one-line reason each, and returns fixes in order of impact. It changes nothing.
Fix once. Claude makes every fix the review confirms, in one pass, keeping anything the review said to keep.
Recheck. Gates run again on the fixed file; the reviewer re-scores only the areas that moved.
Michael approves. He sees the score, the five biggest changes, what was not changed and why, and the questions only he or Brian can answer. His yes makes the page Draft 2 done.
Log and move on. The review file is saved as site-build/REVIEW-&lt;page&gt;.md and the page's row in the build list is marked done.
